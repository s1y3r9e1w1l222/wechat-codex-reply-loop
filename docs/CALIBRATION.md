# 本机校准：开发者操作说明

当前只验证中文微信、440 × 956 点竖屏。`calibrate` 只读当前列表，输出基础结构，`identities` 为空、`verified` 为 false；这不是完整联系人向导。无法可靠获得联系人唯一身份或最新消息边界时，应保持禁用发送。

## 已确认的界面结构

列表 Cell 的标签包含显示名、未读数量／未读标记、预览和时间。免打扰有明确文字或 `bell_off_regular` 图标。完整 Cell 必须在已校准底部之上；底栏遮住的部分行不参与识别。上游工具可能只返回部分节点，适配层只在能核对同一个 observation 的完整缓存节点数量时重建完整树。

扫描顶部当前依赖已知位置的 SearchField。缺少这个证据时停止，不能猜测已回到列表顶部；稳定的多页顺序还需两遍观察一致。该新增扫描保护只经过合成回归，普通联系人完整真机流程仍未验收。

聊天页 `Other` 标签的前缀表示发送方，`我,` 为己方。输入框可能未出现在树中，驱动需结合已确认的语音按钮定位输入区域，再向执行服务读取焦点输入框的实际 value。最新消息位置需有滚动条 100% 证据。未确认这些结构的版式不能沿用本校准。

## 每位允许联系人必须完成的步骤

1. 由设备所有者明确选择测试／回复对象，为本机会话分配不含真实姓名的稳定 ID，例如 `contact_a`。
2. 验证消息列表中该联系人的唯一备注与聊天页标题匹配；同名或群聊不能只靠坐标消歧。
3. 通过 iPhone Use 检查聊天资料和个人资料的可观测控件，取得可重复核对的**唯一身份字符串**。验证进入路径确实通向个人资料，不能拿共用按钮、普通标题作为身份签名。
4. 取得同一联系人的“消息免打扰” Switch，分别确认开／关 value 与含义；看不到开关时状态是 unknown。
5. 验证返回路径回到原聊天，确认发送方、输入框、发送按钮、返回列表和消息尾部。校准过程只读、不输入、不发送。
6. 在私有校准文件写入对应字段；先预览，再在单独授权的测试对象上核对实际发送。每次发送仍重新执行资料核对。

结构示意如下；标有“本机核对”的字符串和 selector 必须替换为实际验证结果，不能直接复制启用：

```json
{
  "list_bottom": 868,
  "viewport": [440, 956],
  "bundle_id": "com.tencent.xin",
  "muted_marker_verified": false,
  "list_region_complete": false,
  "identities": {"本机核对的唯一备注": "contact_a"},
  "profile_signatures": {"contact_a": "本机核对的唯一身份字符串"},
  "identity_probes": {
    "contact_a": {
      "steps": ["本机核对的资料入口 selector"],
      "back_steps": ["本机核对的返回 selector"]
    }
  },
  "verified": false
}
```

`steps` 是按顺序进入资料页的 iPhone Use selector，途中必须观测到精确身份字符串和免打扰开关；`back_steps` 逆向返回原聊天。普通联系人的真实 selector 尚未完成本项目真机验收，不能给所有设备提供一套通用值。

只有实际验证通过，才设置有关标志并把本地 ID 放入配置 `allowed`。校准文件含私人身份，放在私有状态目录，禁止进 Git。文件传输助手自测是单独受控例外，不能用它推定普通联系人身份验证已完成。
