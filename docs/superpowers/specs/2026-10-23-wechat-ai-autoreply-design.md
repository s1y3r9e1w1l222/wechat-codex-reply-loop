# 微信 AI 自动回复服务设计

日期：2026-10-23（Asia/Shanghai）
状态：用户于 2026-10-23 确认；本文是技术设计，不代表功能已实现或真机已验收。

## 1. 意图与已确认选择

用户需要在自己的 iPhone 上，持续处理同一个社交 App 的多个聊天会话：发现新消息、进入会话、依据上下文生成并发送 AI 回复、回到消息列表等待其他会话。

用户已确认：

- 第一版适配微信，不做跨 App 监听。
- 接受 Mac 持续连接 iPhone。
- 回复由 AI 根据聊天上下文生成。
- 采用独立 Mac 服务，复用已安装的 iPhone Use，而非直接修改插件。
- 多个会话未读时，从消息列表最下面的未读会话开始，逐个向上回复，最新的最后回复。

用户随本文确认的首版边界：

- 自动发送只对配置中明确指定的联系人启用；初始名单为空。
- 首版处理文字单聊。群聊、公众号、服务通知、图片、语音、视频和文件不自动回复。
- 开启静音或消息免打扰的群和个人均不进入回复队列；状态无法确认时跳过。排队后开启免打扰则在发送前复核时取消任务。
- 首次启用先预览当前未读队列，再按所选模式运行；不追溯回复已经读过的历史消息。
- 提供预览模式和自动发送模式；默认预览，配置联系人、确认 Codex 登录和发送开关后才自动发送。
- 不逐条请求用户批准日常回复；运行中的暂停、异常和接管通过服务状态表现。

## 2. 目标、非目标与失败标准

目标：让多个允许的联系人可以排队获得基于上下文的回复；发送后回到微信消息列表；等待 AI 时继续发现其他可观察的新消息；暂停后及时停止新的手机操作。

首版不包括：聊天数据库读取、逆向微信协议、跨 App 通知读取、后台隐形控制手机、通讯录全量采集、自动支付、转账、点击聊天链接、知识库或商业客服后台。后续 App 通过适配器扩展，不承诺界面相似就可以零适配。

失败标准：串会话发送、把自己的消息作为新输入重复回复、断线后盲目重发、用不完整或歧义观察假装已经可靠识别会话、宣称可发现不可见且尚未回到列表观察的消息。

## 3. 方案比较与选择

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 独立 Mac 服务调用 iPhone Use | 持续运行、便于调试、业务逻辑与插件升级分开 | 需要单独的服务启动与状态入口 | 用户选择 |
| 在 iPhone Use 插件内直接加自动回复 | 插件内统一启动暂停 | 改动和插件版本耦合，需维护自己的分支 | 本期不采用 |

实现采用 Python 服务，复用 iPhone Use 的 Python Runtime、现有配置、session 和设备操作锁；SQLite 保存业务状态。技术栈是助手的实现选择，用户没有指定语言。

## 4. 现有代码事实

本机检查的插件版本为 0.3.8。当前项目是尚无提交的空仓库，已有插件源代码在本机安装目录，不在本项目中。

- `server/iphone_use.py:Runtime` 提供统一操作入口，共享 `operation.lock` 与 `session.json`。
- 该锁目前只覆盖单次工具调用，不能把多个独立调用自然视为一个原子流程。
- `PhoneController.observe()` 返回扁平化控件、界面文字、位置、前台 App 和视口；默认只返回有限节点，可能截断；没有微信原生消息 ID 或保证唯一的联系人 ID。
- `pua_wait` 是有界控件等待，不是新消息订阅。
- 屏幕流和点击事件是预览/操作能力，不是微信新消息事件总线。
- 本次只检查了配置和源代码，尚未读取当前微信界面，尚未取得本聊天有效 READY，尚未验证微信未读标记的可读取程度。

不直接修改安装缓存。配置显式指定或发现插件路径，启动时核对版本、能力和路径；不把某个版本缓存路径写死到业务代码。

## 5. 组件与边界

### 5.1 服务与控制入口

一个常驻进程拥有业务调度权，提供 `run`、`status`、`pause`、`resume`、`stop`、`calibrate`，以及下文定义的 `resolve`、`retry`、`rebaseline` 入口。首版入口采用命令行和中文状态文本，提供可双击的启动入口；不建设完整桌面界面。用户暂停或停止不依赖 AI 返回。预览是纯粹生成草稿、不发送；本期不建设逐条批准/拒绝草稿的流程，全局启用自动发送后仍要重新核对最新输入。

运行数据单独存放在用户私有目录，目录权限 700、文件权限 600。进程锁避免同一设备启动两个自动回复服务。前台进程启动是首版交付方式；可选登录自动启动后续再做，不默认注册后台任务。

### 5.2 iPhone Use 适配层

复用同一插件的配置、服务和 session，不另建 WDA 会话或更换 state directory 绕过 busy。启动先 setup status，再按现有启动/恢复流程取得 READY；仅复用有效构建，具体签名或信任缺项按原插件流程处理。

所有手机调用由一个工作线程串行执行。AI 网络请求不占用手机锁。一次关键操作事务（核对当前会话、核对消息版本、输入与回读草稿、发送与读取结果）必须在同一共享设备锁内完成，阻止其他 iPhone Use 客户端在中间切页。

适配层可以在本进程内扩展 Runtime 的事务入口，复用其已有校验和控制方法；不修改安装缓存。不得在持有非重入的 `operation.lock` 后再次调用会重取同一锁的 `Runtime.call()`。事务必须有界，出现暂停请求或未知页面即停止；失败保留执行到哪一步，不能自动重放整个事务。

该锁只能约束遵守同一锁的程序，不能阻止用户在手机上触摸。运行时要求手机由服务使用；人工使用前应暂停。每次关键动作前仍验证真实页面。

### 5.3 微信适配器与校准

输出标准对象：`ConversationCandidate`、`ChatSnapshot`、`MessageObservation`。负责识别消息列表/聊天页/未知页，解析会话行、未读与预览，打开指定会话、读取有方向的消息序列、输入、发送、返回列表。

候选和会话快照必须包含三态免打扰标志 `true / false / unknown`。只有可靠识别为 `false` 的允许联系人可排队；`true` 直接排除，`unknown` 展示跳过原因。用户开启免打扰后，即使原任务已有草稿也不发送。

优先使用控件树和局部几何分组，截图和本地视觉识别用于缺失标签或自绘标记。截图不因每次轮询都交给大模型。截图识别器应可替换；首版未校准的版式不自动操作。

校准需要在真实微信上采集脱敏结构和必要页面样本，确认：消息列表行、未读标记、单聊身份、消息左右方向、输入框、发送按钮、返回按钮、最新消息位置。原始个人聊天截图不进入仓库。

联系人由用户从校准得到的唯一候选中选择。仅显示名称不能保证身份唯一；同名且没有可验证身份线索时禁止自动发送，不能以列表索引或坐标当身份。可由用户设置唯一备注后重新校准。

控件树截断、聊天内容缺失或样式未知时不得给出完整性结论。允许有界增加节点或单步滚动，并逐步观察；不能为了找目标连续盲滑。最新消息无法确定时转为需要人工处理。

### 5.4 检测、队列与 AI

消息列表本地轮询间隔初值为 2 秒，可配置；这是检查间隔，不是响应时延保证。实际间隔受 WDA 读取、界面切换和队列影响。

列表顶部有界扫描，新消息通常上浮这一行为必须在当前微信配置上验证。若候选被置顶行遮住或处于屏幕外，按校准的有界扫描策略发现；未覆盖的列表区域不承诺实时发现，状态中展示覆盖范围。

每轮扫描先记录候选会话的实际列表位置，在本轮已覆盖的范围内由下到上建立待回复队列；有分页时先完成有界扫描，再按最后一页到第一页、每页底到顶排列。置顶会话也按实际显示位置处理，不私自改成按时间字段排序。若扫描期间列表变化致使跨页顺序无法可靠对齐，应重新扫描并明确覆盖范围，不声称已取得整个列表的最下面一条。

发现候选后按该顺序读取会话最新文本及上下文，保存输入快照和待处理状态，再返回列表。已读红点消失也不删除待处理任务。连续消息默认等待约 2 秒安静期，最长合并等待 8 秒；达到上限后生成，发送前仍重新检查。

队列分配持久化顺序号，回复造成的会话置顶、列表重新排序不会修改已排好的顺序。处理中后来新发现的消息排在当前未处理队列之后，不插队；待处理会话又有新输入时，旧版本/旧草稿失效，以新版本移到队尾，避免最新消息抢先回复。相同候选的重复观察不改变队列位置。

每个会话只保留一个最新版本的生成任务。AI 并发默认 2，手机并发始终 1；生成可并行，发送必须按队列顺序，不能因后面的 AI 先完成就先发。队首生成失败或身份/输入歧义时，记入可见的待处理状态并移出活动发送队列，再处理后续会话，避免永久堵塞；重试或人工处理后重新入队尾。候选重复、AI 回调乱序和取消失败都按会话版本处理，旧结果不能覆盖新结果。

### 5.5 AI 服务

`ReplyProvider.generate(context, persona, limits)` 返回候选回复或明确失败。用户追加确认：直接复用 Codex 与 iPhone Use 的接入能力，不另外配置模型 API。首版改为 Codex CLI 适配器与离线假实现。

本机确认 codex-cli 0.164.0 已通过 ChatGPT 登录。独立服务通过 `codex exec` 的非交互入口复用现有登录，使用临时会话、结构化输出和标准输入传递上下文；不读取或复制认证令牌。具体模型可配置，默认不强制覆盖 CLI 默认模型；不声称继承当前聊天的全部历史或设置。

生成进程忽略用户配置以免加载其他 MCP、禁用插件/Apps/命令执行等工具，使用只读沙盒与禁用网络搜索；不使用绕过审批或沙盒的参数。其唯一业务产物是回复文字，手机操作仍由共享 iPhone Use Runtime 执行。上下文与临时结果在私有临时目录中处理，完成后清理；数据处理遵循现有 Codex 账户规则，不承诺服务端无日志。

每个会话最多送入最近 20 条已确认方向的文字消息、总计约 8000 字符，默认生成一条不超过 300 字的回复。新增输入若自身超限或包含尚未处理的非文字内容，转人工处理，不默默截断后假装完整回答。

口吻由本地配置/提示词文件控制；默认中文、简短、自然，不编造用户个人经历或已执行的操作。聊天内容作为数据提供，不允许其修改联系人名单、配置、执行手机动作或请求其他会话内容。AI 只生成文字，无工具执行权。

草稿含换行时转换为等价单段文字后重新回读；首版不直接把多行文本交给微信输入框以免回车提前发送。空回复、拒绝、非完成状态、超长输出或解析失败均不发送。

每次请求有超时，生成失败可有界重试且保留任务。Codex 未登录、不可用或生成失败时保留任务并展示错误类别；超时和取消会终止本次生成进程，旧结果不能发送。离线回放不需要登录；自动模式必须检查 Codex 可用。

## 6. 消息身份、上下文与去重

界面没有可靠原生消息 ID 时，不承诺 exactly-once。服务偏向在不确定时暂停发送，而不是猜测并重发。

每个会话使用本地 ID 和已校准身份签名。保存按顺序排列的消息观察：方向、类型、完整文本、可见时间锚点、相邻消息上下文及本地顺序编号。内容相同的两条消息必须保留两次，不能仅对文本做集合去重。

新旧快照采用有序重叠匹配。只有在重叠、方向和尾部锚点可以唯一解释时才追加观察并提升会话版本；重复文本导致多种解释、缺乏重叠或页面不是最新位置时标记 `ambiguous`，不生成可自动发送任务。

首次启用或新增联系人先校准并建立观察基线，同时将当前允许联系人的未读会话列入预览队列，按列表底到顶排列。用户启用自动发送模式后，可以处理这批明确列出的未读会话；不额外追溯已经读过的历史消息。已有未读数量或边界无法可靠确定时，仅展示上下文和待处理原因，不猜测应回复哪段历史。服务运行中读取到的新输入独立持久化，不依赖未读角标一直存在。

上下文仅来自该会话本地采集记录与本次可验证的最新界面，不跨联系人混用，不宣称已读取全量历史。重启后先核对快照，不直接续发旧草稿。

## 7. 状态与发送过程

服务状态：`starting / monitoring / paused / recovering / needs_attention / stopping / stopped`。

会话任务状态：`pending / generating / draft_ready / sending / sent / stale / failed / ambiguous / uncertain`。任务包含会话 ID、输入版本、运行代次、扫描轮次、来源列表位置、持久化队列顺序号和草稿摘要。

发送事务：

1. 核对服务未暂停、名单与发送模式仍有效、运行代次匹配，并确认该会话当前未开启静音/免打扰；已开启或未知则取消待发送任务。
2. 打开并核对正确单聊，读取最新尾部；如版本改变则作废旧草稿，重新生成。
3. 若出现用户手写草稿，保留它并转人工，不自动覆盖。
4. 输入完整单段回复，处理工具要求的长文本续传，核对完整草稿与目标。
5. 在数据库提交 `sending` 和发送前尾部快照，再点击一次发送。
6. 核对自己的新消息气泡与完整文本确已出现，并排除显式发送失败；此证据只说明界面中的发送结果，不声称对方已收到或已读。
7. 数据库提交 `sent`、更新水位，返回消息列表。

步骤 5 后超时、崩溃或失联时保持 `uncertain`。恢复只读核对：只有唯一的新增己方气泡与发送前快照吻合才可记为已发送，否则需要人工确认；不会因为没找到而再次发送。草稿仍在也不能单独证明从未发送。

最后核对后到发送点击之间仍可能有对方新消息到达；普通屏幕控制无法提供微信服务器级事务。服务应缩短该间隔，后续观察发现新输入时再安排下一轮，不声称完全消除此竞争。

## 8. 暂停、恢复与故障

暂停立即使当前运行代次失效，阻止新生成结果进入发送。正在进行的单个不可中断调用最多等待其有界超时；不承诺撤回已经发生的发送。允许生成请求在后台结束，但其旧结果不再发送。

离开微信、出现未知页面、认证页、人工草稿、身份歧义或无法核对消息尾部时暂停该操作；不自动点击未知弹窗。普通可识别的导航错误先观察再恢复；认证/解锁沿用 iPhone Use 的用户接管流程，等待用户实际完成。

`device_busy` 有界等待，不绕锁、不重放输入。WDA 断线只恢复已核验归属的现有服务；业务任务始终重新观察。恢复后回到已知消息列表并重建对齐；失效草稿不得直接发送。

恢复监控默认需要显式 `resume`。进程重启进入核对/预览状态，保留 `uncertain` 任务，不自动武断补发。

人工处理入口是助手确定的首版规则：

- `resolve <job> --outcome sent`：用户核对确已发送后，仅将记录标为已发送，不执行手机动作；保留人工确认来源。
- `resolve <job> --outcome handled|abandoned`：用户已手工处理或决定放弃，结束该任务且不发送；再次观察并对齐后才允许处理未来新输入。
- `retry <job>`：仅允许生成失败或已解决识别歧义的任务；必须重新观察并确认身份、输入和名单，创建新版本排到队尾。不能对 `sending/uncertain/sent` 执行重发。
- `rebaseline <conversation>`：用户在手机上处理完人工草稿、非文字消息或歧义后，显式重新校准最新尾部，结束旧待处理项，仅监控之后的新输入。若仍无法对齐，保持待处理。

普通 `resume` 不等同于上述解除动作。命令通过服务本地控制通道交给唯一调度者执行，不能由另一个进程直接修改运行中队列。控制通道仅限本机同一用户，检查权限并限制请求大小。

## 9. 配置、数据与运行记录

配置包括：插件路径/能力版本、允许的联系人、Codex 命令路径、可选模型与 provider、口吻文件、预览或发送模式、检测与合并间隔、上下文上限、请求超时。未知配置键和越界值拒绝启动。

SQLite 最少包含 conversations、message_observations、reply_jobs、send_attempts、service_state。事务更新输入版本、任务和发送状态，记录可恢复检查点。

API key 不写入配置示例、数据库、Git 或常规日志。运行日志默认只保留状态、匿名会话 ID、耗时和错误类别；聊天原文只放私有本地状态，提供清理入口，建议保留最近 7 天。允许按需导出脱敏诊断。

使用 Codex 生成时，允许联系人会话内被选中的上下文会通过已登录的 Codex 处理；启用前展示 Codex、联系人范围和当前发送模式。预览模式允许生成草稿但绝不点击发送，仍可能读取消息并使微信标为已读。

## 10. 验证与交付标准

自动化验证重点覆盖真实风险，而非逐行复制实现：

- 微信脱敏样本：页面识别、控件截断、红点、消息方向、同名联系人、相同文本连续两次、无重叠历史、非文字输入、免打扰群/个人不入队、未知免打扰状态跳过、生成后开启免打扰取消发送。
- 调度回放：多个未读按列表底到顶发送、跨页候选逆序、置顶会话按实际位置排序、回复引起列表重排但队列不变、新消息排队尾、排队会话再次来消息移到队尾、后面的 AI 先完成不能越序、队首失败可继续其他会话、已读后仍有任务、AI 失败与限流。
- 发送故障注入：输入中断、草稿不符、用户已有草稿、按下发送后超时、发送后落库前崩溃、重启恢复、暂停与发送竞态。
- 适配层：共享锁跨进程互斥、关键事务不能被另一个 iPhone Use 调用切页、未知版本拒绝、网络请求期间不占用设备锁。
- AI：Codex 命令合同、工具隔离、取消/超时、结构化输出解析、上下文隔离、未登录和离线假实现。

真机验收与模拟测试分开：先只读校准，再生成预览，最后在用户明确指定的测试联系人中验证自动发送。用户已明确允许使用文件传输助手做发送测试；该自测入口只向自己发送，不把文件传输助手加入普通自动回复名单或触发自回复循环。

只读校准是自动发送实现的先行可行性门：先验证当前微信版式是否有足够的身份、未读和消息方向证据。树缺失时，本期可做针对当前版式的最小本地视觉适配并用真实脱敏样本验证；没有足够身份/消息证据时，自动发送保持禁用，展示具体缺项和预览结果。此时不能把只完成离线流程称为整体完成；若继续需要扩大识别方案或改变支持范围，带回实测证据让用户决定，而不无限尝试或伪造成功。

完成标准：提供能启动/暂停/停止的服务、配置示例、中文使用说明和通过的回放/故障测试；真机证明列表到单聊再回列表、两个会话排队、上下文生成、发送结果核对与不确定状态暂停。Codex 未登录或没有可靠真机身份校准时应明确标注相关真机步骤待完成，不能宣称整项已验收。

## 11. 待配置事项与实现者可自行决定的事项

上线前由用户配置：允许的普通联系人、可选 Codex 模型、个人回复口吻；测试目标已确定为文件传输助手。它们不阻止离线实现，但缺少联系人校准时不能向普通联系人自动发送。

实现者可自行决定：模块命名、SQLite 迁移方式、测试框架、退避细节、脱敏样本格式、启动入口文件布局。前提是保持本文的行为与发送边界。

当前真实风险：微信界面可能缺乏足够稳定的未读标记/消息方向/身份锚点。若校准证明无法可靠获得，必须报告具体缺项，再决定视觉适配或收窄支持范围，不能用虚构样本宣称可用。
